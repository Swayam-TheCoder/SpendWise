Overall flow:
Forgot Password
      ↓
Enter email
      ↓
Generate random reset token
      ↓
Hash token
      ↓
Store hash in DB
      ↓
Send email
      ↓
User clicks reset link
      ↓
New password
      ↓
Verify token
      ↓
Hash new password
      ↓
Update password
      ↓
Invalidate existing sessions


For security purpose, we have
Reset token
     ↓
randomBytes(32)
     ↓
SHA-256 hash
     ↓
PostgreSQL

Actual token
     ↓
Email only
and token time is 15 minutes


Now, Reset Password
Flow:
User clicks email link
        ↓
token + new password
        ↓
Find token hash
        ↓
Check expiration
        ↓
Hash new password with Argon2
        ↓
Update User
        ↓
Delete reset token
        ↓
Delete all existing sessions
        ↓
Password reset complete

why delete all the sessions?
Laptop      → logged in
Phone       → logged in
Old browser → logged in

Then the password gets reset.
We don't want those old sessions to remain active:

Password reset
      ↓
Delete all sessions -> laptop, phone, old browser

Password reset system would be:
Forgot Password
       ↓
15-minute reset token
       ↓
Email
       ↓
Reset Password
       ↓
Argon2
       ↓
Invalidate sessions
       ↓
Login with new password
